# Мониторинг Мастерской

Отдельный публичный мониторинг: GitHub Actions запускает Globalping из шести
российских городов и сетей. Финляндия исключена из текущего набора.
Ни код приложения, ни данные клиентов, ни доступы к Yandex Cloud сюда не входят.

## Где смотреть

- [Последний результат и история инцидентов](https://github.com/KlochkovN/masterskaya-monitoring/issues)
- [Запуски и их результаты](https://github.com/KlochkovN/masterskaya-monitoring/actions)

Проверяем основной сайт, API через edge и прямой API Яндекса. Сайт и edge
используют одну VM — это разные пути доступа, а не два независимых сервера.
Ожидаемый отказ HTTP 401 у API подтверждает путь до функции авторизации;
это **не** проверка YDB, расписания, входа пользователя или сохранения данных.

Точки проверки (страна, город и ASN проверяются в каждом ответе):

| Город | Сеть | ASN |
|---|---|---:|
| Москва | Timeweb | 9123 |
| Санкт-Петербург | Selectel | 49505 |
| Кострома | Ростелеком | 12389 |
| Пенза | Дом.ру / ЭР-Телеком | 41754 |
| Уфа | Билайн / ВымпелКом | 3216 |
| Новосибирск | МТС | 8359 |

Узлы найдены в публичном списке Globalping 20 ноября 2026. Их наличие может
меняться. Узел в сети оператора не доказывает, что подключён через LTE;
это не проверка всех абонентов или всех сетей России.

## Оповещения

При подтверждённой проблеме создаётся issue с упоминанием владельца. При
восстановлении приходит комментарий, issue закрывается. Успешные проверки
не создают отдельных оповещений. Два измерения при проблеме выполняются в
одном запуске с паузой 10 секунд. Расхождение или отсутствие данных означают
неизвестную доступность, а не доказанный отказ Мастерской.

Неизменная проблема не порождает повторных писем через каждый интервал.
При изменении статуса или восстановлении приходит новое сообщение; колебания
статуса между запусками могут вызвать несколько писем. Замена набора сетей
закрывает старое предупреждение с пояснением, а не с ложным сообщением
о восстановлении исключённого узла.

Email-оповещения отправляет GitHub, а не почта Мастерской. Их доставка зависит
от настроек аккаунта владельца. Ручной запуск с `test_alert=true` создаёт явно
помеченное тестовое уведомление, не отключая приложение.

## Границы и обслуживание

- Расписание — раз в 10 минут. GitHub может задержать или пропустить запуск.
- Если последнему результату больше 15 минут, доступность неизвестна. Issue
  не умеет автоматически менять цвет, когда GitHub остановился. Независимого
  наблюдателя за самим GitHub пока нет.
- GitHub может отключить расписание публичного репозитория после 60 дней без
  активности. Проверяйте состояние расписания хотя бы ежемесячно; обновления
  issue нельзя считать гарантией, что этот механизм никогда не сработает.
- Проверки идут из дата-центров и сетей доступа, не из всех мобильных сетей России.
- Без токена Globalping даёт 250 проб/час на IP; IP GitHub может быть общим.
  Обычный режим: 6 сетей × 3 адреса × 6 запусков = 108 проб/час,
  максимум с повторными подтверждениями — 216.
  Ручные запуски добавляют расход. Ошибка лимита отображается как отсутствие
  данных, покупки кредитов и автоматического повышения лимита нет.
- При необходимости добавьте `GLOBALPING_TOKEN` только в GitHub Actions
  Secrets: отдельная учётная запись даёт 500 проб/час. Не в файлы и не в чат.
- Токен GitHub краткоживущий и ограничен этим репозиторием: чтение файлов и
  работа с issues. Постоянный PAT не требуется. Workflow не запускается из PR.
- Тела ответов, cookies и авторизация Мастерской не сохраняются и не отправляются.
- MAX, почта, платежи, база и настройки PROD не изменяются.
- Интеграция с административной консолью Мастерской пока не подключена.

## Проверка и остановка

Локальные тесты: `node --test` (без сети). Проверяются ответы,
ошибки провайдера, создание инцидента, отсутствие дублей и восстановление.
Остановка: Actions → Availability — Globalping → Disable workflow.

Источники: [Globalping](https://globalping.io/credits),
[расписание GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
